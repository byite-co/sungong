# 원본 사진 해상도 — ⛔ 아직 실측되지 않았다

## 상태

**미측정.** 이 문서는 측정 방법과 검증식을 고정해 두는 자리다.
숫자는 `tools/photo_dims.mjs` 를 사진이 있는 곳에서 돌려 채운다.

`eval/photos/` 는 `.gitignore` 대상이라 저장소에도, CC 컨테이너에도 없다.
실행은 사진이 있는 총괄 PC 에서 한다:

```
node tools/photo_dims.mjs --photos photos/test10 --out notes/photo_dimensions.md
```

이 명령이 이 파일을 실측 결과로 덮어쓴다. API 0회.

## 왜 실측이 필요한가

결정기록 §5-B 의 밀도 계산이 **"원본 4032×3024"** 라는 추정에 얹혀 있다.
그 값은 관측된 조각 높이 869 에서 역산한 것이고, 아무도 파일을 열어 확인하지 않았다.

역산은 맞아떨어진다 — `sliceBoxes(3024, 4, 0.15)` 의 첫 조각이 정확히 **869** 다:

```
$ node -e 'import("./tools/crop_eval.mjs").then(m=>console.log(m.sliceBoxes(3024,4,0.15)))'
  [ { index:1, top:0, height:869, bottom:869 }, ... ]
```

따라서 **세로 3024 는 조각 높이와 정합한다.** 다만 이것은 여전히 역산이고,
가로가 4032 라는 근거는 없으며 10장이 서로 같은 해상도라는 근거도 없다.

## 검증식

```
조각높이 합 − 원본높이 = 겹침 픽셀
겹침 픽셀의 이론값 = (조각수 − 1) × 2 × overlap × (원본높이 / 조각수)
```

4등분·겹침 0.15 기준 합성 이미지로 검증한 결과(도구 동작 확인용, 실제 평가셋 아님):

| 원본 | 조각 크기 | 조각높이 합 | 실측 겹침 | 이론값 | 일치 |
|---|---|---:|---:|---:|---|
| 4032×3024 | 4032×869, 4032×982 | 3702 | 678 | 680 | ✅ |
| 3024×4032 | 3024×1159, 3024×1310 | 4938 | 906 | 907 | ✅ |

(±조각수 이내 차이는 반올림 오차다.)

## 10장이 서로 다른 해상도라면

그대로 적는다. **장별로 이미지 토큰 배수가 달라진다**는 뜻이고, 그러면

- "장당 이미지 토큰"을 하나의 수로 말할 수 없다
- 크롭의 예산 배수(조각 4개 ≈ 페이지 1장의 4배)도 장마다 달라진다
- README 의 원가 사다리 수치는 대표값이지 모든 장에 적용되는 값이 아니다

`tools/photo_dims.mjs` 가 이 경우를 감지해 경고 문단을 출력한다.

## 도구

`tools/photo_dims.mjs` — sharp metadata 로 읽는다. API 0회.

import 해도 판독이 돌지 않게 했다.
